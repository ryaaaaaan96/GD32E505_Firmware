# 公共接口设计规范

本规范用于新增或修改 app 设备访问接口、device 接口和 platform 公共接口。
现有接口的具体行为仍以其头文件契约为准；不因本文件新增而静默改变行为。

## 核心原则

同类设备跨平台接口一致；不同设备遵循统一的命名、类型、错误及生命周期规范，
但保留各自的操作语义，不强制使用同一个通用函数入口。

- 保留 aDevUsartRead/Write、aDevLedSet/Toggle 等类型明确的接口。
- 不为了形式统一，引入 aDeviceRead/Write/Control 或 void* 通用句柄。
- 不要求所有设备都有 Read/Write，也不要求参数数量相同。
- API 不暴露具体 MCU 寄存器、厂商库类型、FreeRTOS/Linux 私有类型。
- aDrv 负责非阻塞硬件操作；device 负责设备语义；aOS 提供时基、等待和执行上下文相关能力；app 决定资源和初始化顺序。

## 命名、参数与类型

- 自研编译能力开关统一命名为 `<模块>_<功能>_ENABLE`，值为 0/1，使用 `#if` 判断；不使用 `HAS_*` 命名。CMake 的请求与解析变量不属于 C 宏，仍按构建规范命名。运行状态查询（如 HasRxOverflowed）和第三方原生接口不改成 Enable，避免混淆查询与使能操作。
- 同语义使用相同动词：Init、Open、Read、Write、Set、Get 等；不同语义不能只靠平台实现暗中区分。
- 常规操作参数按句柄、数据/长度、选项/超时排列。Init/Open 等遵循配置或 ID 在前、输出句柄在后的形式。
- 输入缓冲区只读时使用 const；容量和长度使用 size_t，逻辑值使用 aBool_t/A_TRUE/A_FALSE。
- 多个关联选项可封装成请求结构体；不能为了减少参数把无关状态或运行时内部字段公开。
- 字节流接口长度统一为字节；采样、块设备等非字节单位必须在参数名和注释中明确，禁止隐式混用。
- 同一类型的接口在不同平台保持参数、单位、返回值、超时和所有权语义一致，不只保持函数名一致。

## 公共头文件注释

自研对外头文件以 `device/aDev_usart/include/aDev_usart.h` 为格式参考，采用中文
Doxygen 注释。第三方/官方原始头文件不做批量风格改写。

- 文件头使用 `@file`、`@brief`，说明层级职责、默认调用上下文和生命周期。
- 每个公开函数使用 `@brief`；逐个填写 `@param[in/out/in,out]`，注明单位、
  有效范围、NULL/零长度规则与输出何时有效。有返回值时填写 `@return` 或 `@retval`。
- 配置字段说明默认值、必填项和资源含义；回调说明执行上下文、参数所有权及有效期。
- 阻塞、线程/ISR 安全、锁、超时预算、取消和资源释放限制使用正文、`@note`、
  `@warning` 说明；不把提交成功、DMA 完成和线路完成混为一谈。
- 写当前实现的真实契约，不把设计目标写成已有保证。保留字段、端口限制、没有完成
  屏障等限制须明确标出；修改实现时同步更新头文件，不仅更新独立设计文档。
- 单纯类型/宏定义可以用简短注释；禁止给无返回值函数虚构返回码或复制无关错误列表。

## 返回值和错误

- 普通可失败操作返回 aStatus_t，数据通过输出参数提供。不新增模块私有的重复状态枚举。
- 流式数据传输返回 aSSize_t：非负为实际传输字节数，-1 为失败，由 aOS 的 errno 接口提供原因。
- 非负返回时不得读取 errno 判断本次调用成败；成功不承诺清除旧 errno。
- 部分传输、零长度、无数据、超时和取消的行为必须明确。流式接口允许返回部分长度，不将已完成的进度隐藏成无条件 -1。
- 异步提交返回 aStatus_t，仅说明请求是否接受；最终传输结果在回调事件中报告，不通过回调线程的 errno 回传。
- 能力被编译关闭时可按能力宏隐藏声明；功能已编译但当前硬件/模式不支持时，按接口契约返回 UNSUPPORTED 或对应 errno，不能伪成功。

## 超时和执行上下文

- 使用 aTimeout_t，统一表达不等待、有限等待和永久等待，不重复定义超时类型。
- 有限超时通常约束一次调用的总等待预算，不能在每次内部重试时重新开始计时；特殊语义必须另行注明。
- 不等待不代表请求一定成功，也不应启动之后无法在返回前停止的同步硬件操作。
- 公共头文件必须说明能否阻塞、能否从 ISR 调用，以及锁和并发限制。
- 业务异步回调默认在 aOS 任务/线程上下文执行；确需 ISR 回调时，必须通过明确的独立 API 或显式配置说明，禁止因后端不同而静默变化。
- 回调可能何时发生、能否重入/提交新请求、取消如何完成，都必须在接口中说明。

## 缓冲区和完成语义

- 明确是否复制、缓冲区由谁持有、何时可复用或释放；DMA 不自动等于零拷贝。
- Direct 若承诺零拷贝，不能在不支持时悄悄退化为复制；应返回不支持。
- 区分提交成功、内部缓冲区接收、DMA 搬运完成和外设真正完成。
- USART DMA 完成不等于线路发送完成；标为线路完成的事件必须以 USART TC 等等效状态为依据。
- 异步请求描述符与数据缓冲区的生命周期分别说明。接收回调的数据是借用视图还是稳定快照，也必须明确。

## 应用设备按实例初始化

- 每类提供 Init(id, &handle)：appSystemConsoleInit、appSystemStatusLedInit，保持类型明确，不新增通用 void* 接口。
- 合并初始化和句柄获取，不再提供独立 Open。第一次调用初始化选中实例，后续返回同一句柄或保存的错误。
- 失败清空输出；NULL 输出指针返回 INVALID_PARAM，未知/未配置编号返回 NOT_FOUND。
- 首次初始化可能耗时、分配 OS 资源并操作硬件，不能当作无副作用查询。
- 仅在驱动/OS 就绪后、启动阶段单线程调用；同实例重入返回 BUSY，不表示线程安全。
- 每实例保存自己的生命周期结果，不因其他设备初始化失败自动回滚。失败不自动重试。
- 不在运行时检查跨设备资源冲突；后续可通过 Python/CMake 添加构建期告警（当前未实现）。设备本身的参数、能力和初始化错误校验仍须保留。
- 句柄为共享借用，禁止销毁、重新配置或反初始化；没有隐含独占锁或独立接收流。
- 运行阶段使用或传递已获得的句柄，不依赖运行期首次 Init。
- 不在各层机械复制 initialized 状态；应用的初始化阶段/结果用于管理该实例的幂等初始化，不替代底层有效性检查。
- 如需查询不初始化、热重配置或运行期并发首次初始化，必须显式扩展契约与测试。

## 新接口审查清单

1. 同语义接口是否保持命名、参数顺序、类型和单位一致？
2. 返回值、部分进度、errno 有效条件和超时预算是否明确？
3. 缓冲区所有权、句柄生命周期和完成条件是否明确？
4. 调用/回调上下文、并发、取消和重入是否明确？
5. 能力关闭、硬件不支持、非法参数、失败路径是否测试？
6. 是否无必要地引入通用函数入口、void* 或平台专有类型？

本规范不自动变更现有 API，不引入通用 ops 框架；实现迁移必须同步代码、注释和测试。
## 任务与执行上下文

func 不创建/删除业务任务，任务创建、栈、优先级、运行循环及退出顺序属于 app/task。
func 提供 Init/Process/DeInit 等无任务所有权的入口，允许由任务或裸机主循环驱动。
OS 内核服务和 aOS 的共享延迟工作队列仍属于平台实现，不属于应用业务任务。
worker 上下文的回调不允许阻塞，即便它不是 ISR；耗时工作转交应用任务。
对象销毁前先停止新提交、停止业务调用者并等待在途操作结束，不使用强制删任务
代替同步退出。Init/DeInit 默认不与其他 API 并发，除非对应接口显式承诺。

## 统一超时与 errno

aLib 定义 aTimeout_t、aTimepoint_t 和纯时间计算；aOS 提供单调毫秒时基、等待及
当前任务的 errno；device 实现操作等待；func 分配整个流程预算；app 决定具体值和恢复策略。
aCore 不提供第二套 uptime，aDrv 不读系统时钟、不进行软件超时轮询。
启动阶段晶振保护等待和外设硬件 timeout 不等同于公共软件等待接口。

| 等待要求 | 语义 |
|---|---|
| A_TIMEOUT_NO_WAIT | 仅立即尝试；无进展通常为 A_EAGAIN |
| A_TIMEOUT_MS(n) | 总等待预算；无进展且到期通常为 A_ETIMEDOUT |
| A_TIMEOUT_FOREVER | 不设软件截止点，仍可能被错误或取消结束 |

有限操作在入口调用 aTimepointCalc(timeout, aOSGetUptimeMs())，
后续步骤使用 aTimepointRemaining()，不能每次重试重新获得完整预算。
时间计算使用无符号差值处理 32 位计数回绕，不直接比较 now >= deadline。
具体类型和边界以 [aLib.h](../platform/aLib/include/aLib.h) 为准。

FreeRTOS 后端将有限毫秒向上转换为 tick，errno 保存到任务局部存储。
调度器尚未运行或被暂停时不能依赖 tick 推进执行有限/永久阻塞等待；
NO_WAIT 仍可立即尝试。Linux/裸机只是移植目标，目前没有对应后端。

aOSWaitObject 使用保留的任务通知 index 1，允许一个等待者，pending 锁存提前通知。
通知可以合并；使用者按“检查条件—等待—再次检查”循环，不能把一次通知当成一个字节。
中断/DMA 路径通过等待对象真正阻塞；纯轮询路径的 yield 只让出执行权，不等于睡眠。
USART Direct 的具体等待方式见 [USART 设计](usart_design.md)。

aDrv 返回 aStatus_t，不读写 errno。aStatusToErrno 是 aLib 的纯映射；
aOSFailWithStatus/aOSFailWithTimeout 设置任务 errno 后返回 -1。
只有流式调用返回 -1 才查询 aOSGetErrno；部分成功优先报告长度，异步结果由事件携带。
ISR 不使用任务 errno。各接口对取消、NO_WAIT 和部分进度的例外以公共头注释为准。
