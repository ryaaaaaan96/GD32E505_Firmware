## 已修改

| 问题 | 修改 | 收益及边界 |
| --- | --- | --- |
| Flash 设备初始化还启动 aMemory 和数据库 | aSystemInit 显式编排设备、分区、业务服务；appDatabaseInit 管理数据库模块初始化 | 设备初始化不再依赖数据库是否启用，依赖顺序可直接阅读 |
| Shell 任务先于数据库和 SIG 初始化运行 | 提前初始化 Shell 队列，最后创建 Shell 任务 | 阻塞探测或恢复数据库时，命令不会与服务初始化交错；启动信息统一稍后发送 |
| 数据库只需点表定义，却包含完整 aBus API 和配置限制 | aBus_table.h / aBusTable 单独提供只读契约 | ABUS_ENABLE、两种分配接口均关闭时仍可使用数据库，无运行库依赖 |
| 动态业务目标被传播 FlashDB / nanoMODBUS 的内部配置 | 动态构建改为私有依赖；静态构建保留布局必需的公开依赖 | 减少头文件和配置耦合，不增加运行包装层；静态实例布局仍非稳定 ABI |
| aBus 初始化每个 SIG 都从首表重新找定义 | 按表和条目顺序推进，并合并数据地址分配与默认值写入 | 这几遍从最坏 O(SIG 数 × 表数) 降为 O(SIG 数 + 表数)，无额外 RAM |
| USART 中断缓冲读取逐字节进出临界区 | 连续区间在临界区外 memcpy，仅保护快照和提交 | 连续 7 字节从 7 次临界区降为 2 次，回绕用 4 次；复制期间中断保持可用 |
| USART ISR 每字节用运行时容量取模 | 单步游标改为递增后比较回绕 | RX 入队和 TX 出队不再需要除法，仍支持非 2 的幂容量 |
| 架构检查把未编译的上游异步插件和示例也当作自有代码 | 明确排除上游目录，增加公共头独立编译与点表独立使用检查 | 修复原检查误报，保留对自有适配代码和层间依赖的约束 |

aBus 的设备号去重与绑定查找不属于此次线性遍历优化。sigIndex 在定位设备后
仍为直接索引，sigKey 仍线性查找，未引入哈希表、缓存句柄或额外运行对象。

USART 优化只针对中断缓冲读取，不改变 DMA 覆盖检测、Async ISR 回调、数据
稳定性、超时及所有权语义。rx_mutex 保证单消费者；数据被复制完之前仍计为
占用，ISR 遇到满缓冲丢弃新字节，不覆盖正在复制的数据。此证明基于当前单核
MCU 的临界区契约；将来 Linux 后端仍须使用真正的线程同步。

## 继续保留的设计

- aLib 保持纯类型和工具；aDrv 不依赖 aOS，设备的等待和并发留在 device。
- aMemory 通过应用提供的操作表访问介质，aDataBase 不依赖 Flash25Q。
- aModbus 直接依赖 aBus，这是已确定的产品数据模型，不添加 backend 目录。
- func 不创建业务任务，app 持有任务、初始化顺序和服务生命周期。
- 静态实例允许显式布局头；动态业务只使用不透明句柄，不增加固定大小存储壳。
- 绑定变量的直接并发访问继续由应用决定；本次不新增业务锁或原子字段。

## 剩余边界与后续优先级

| 优先级 | 当前情况 | 建议 |
| --- | --- | --- |
| 高 | FlashDB、SFUD、EasyLogger、nanoMODBUS 在主仓库中仍是 gitlink；根目录没有 .gitmodules，当前工作区存在源码不等于新检出能复现 | 统一选择普通受控源码目录或完整的子模块交付方式；FlashDB 的本地修改目前另由 patches 保存，本次未迁移依赖源码 |
| 高 | Linux aOS 尚未实现；顶层构建明确只接受 Embedded/FreeRTOS | 下一步独立实现 POSIX 后端，复用业务模块测试，明确临界区、等待、时钟和关闭契约；主机替身测试不等于已支持 Linux |
| 中 | SPI Flash 仍逐字节轮询；每字节多次驱动和时钟调用，批量读写占用 CPU | 先在板上测吞吐与 CPU 占用，再决定增加 aDrv 块传输或 DMA；本次不更改已验证的 SPI 时序 |
| 中 | SFUD 写路径使用共享静态页缓冲，Flash25Q 模块锁覆盖完整操作；数据库也使用模块级锁和事务状态 | 当前多实例会串行，不能只删除全局锁；确有多介质并发需求时再把共享状态改为实例私有 |
| 中 | Modbus 映射读写会重复解析目标，且为最大协议数据准备临时栈空间 | 先按业务寄存器表测量栈峰值和每帧时间；缓存定义需用额外 RAM，暂不以复杂度换未经测量的收益 |
| 中 | aBus 未强制排序 deviceID/sigKey，按 key 查找与多设备定位仍线性 | 高频业务优先使用 sigIndex；设备很多时再考虑排序定义或构建期索引，避免所有条目预留 RAM |
| 中 | 日志输出在日志锁内同步调用后端 | 当前 Shell 后端仅排队，开销有限；未来直接接 Flash 会阻塞调用者，应由应用决定是否加入有界异步队列 |
| 中 | Shell 长命令期间不消费自身输出，持续大批量打印可能丢弃；可选 stream.flush 不自动调用 | 继续遵守现有队列和直接提交流契约；分页输出或缓冲流适配需另行明确，未擅自改变 flush 语义 |
| 低 | 顶层产品仍必须配置 MCU/链接脚本，静态实例头会依赖上游布局 | 为实际 Linux 产品接入时再分开平台选择；不预先增加未实现的平台层 |

数据库 SIG 索引已避免常规读写遍历历史 KV，但启动恢复、GC 和扇区分配仍有
扫描，不能承诺恒定追加延迟。CRC 校验和故障恢复属于必要正确性成本，不为
减少 I/O 次数而取消。当前 4 字节热更新的主机用例仍为 5 次介质读回调。

初始化失败仍按现有停机策略处理，不提供全系统事务式回滚；最后启动 Shell
意味着 Flash 探测或数据库恢复较慢时提示符也会稍后出现。硬件调试可读取
aOS 故障记录，本次未增加另一个初始化阶段的命令执行线程。

## 验证

- 架构边界、公共头独立编译、aBus 定义独立于分配和锁配置。
- aBus 36 种锁、定义检查、NDEBUG、静态/动态组合及空注册段。
- USART 环形回绕、非 2 的幂容量、复制窗口内中断、满缓冲丢弃、DMA 和 Async 回归。
- 实际 system.c 的成功及各阶段失败路径，验证 Shell 任务仅在最后创建。
- Shell、aOS、aMemory、日志、Modbus、Flash25Q、应用设备与 SIG 主机回归。
- 真实 FlashDB KV/TSDB、SIG 索引、GC、重开、故障注入及完整 Flash 适配链测试。
- Debug 固件与 USART、数据库、Modbus 构建矩阵，含无 aBus 运行库的数据库构建。

该轮 Debug 固件链接占用 Flash 79,380 字节、静态 RAM 33,176 字节，无编译告警。
这不是运行时堆或任务栈峰值；未做本轮上板吞吐、IRQ 延迟及真实掉电测试。
